# 文档说明

员工服务智能体首个版本交互细节较多，以文档形式描述用户端的UED方案，部分Mock数据可能会引起误导，具体数据及智能体执行逻辑以PRD为准，UI最终细节以Figma设计稿为准。

| 一级标题 | 二级标题 | 左侧导航（左） | 对话流（中） | 独立面板（右） |
|---|---|---|---|---|

| | 最小宽度 | 固定 240px | 420px | 320px |
| | 拖拽调整宽度 | -- | 支持，鼠标悬停时边缘样式需有明显变化 | |
| 关闭独立面板时 | 总宽度 ≥ 660px | 240px | 自动，撑满剩余空间 | -- |
| | 420px ≤ 总宽度 < 660px | 自动收起，抽屉方式展开 | 自动，撑满剩余空间 | -- |

用户在自定义插槽中选中某个“**子智能体**”，子智能体切换为已选中标签状态，推荐指令刷新为已选中子智能体对应的指令，点击向输入区带入「指令文字」，并隐藏掉整个推荐区；

当存在已选中的子智能体时，用户可以在选中标签右侧点击「x」按钮删除选择，但不会删除输入框中的文本和技能，删除后，自定义插槽恢复到初始状态

### 文本

填充气泡的展示形式，根据内容长度的不同，存在以下形态：

- **单行短文本**：字数较少，没达到气泡的最大宽度；
- **多行文本（≤8行）**：达到气泡的最大宽度，但在8行以内时，以气泡的最大宽度（540px）换行显示；
- **多行文本（＞8行）**：内容超过8行时，在最后显示「展开」按钮，点击后气泡高度不再显示，展示全部的文本内容，同时按钮消失，直至页面重新加载；

### 工具栏

文本气泡下方为「工具栏」区域。

**显示逻辑**

- 桌面端：默认不显示（但区域高度需要始终保留），鼠标悬停在文本气泡时显示；
- 移动端：永远不显示；

**消息发送时间**

- 仅桌面端显示，格式为：07月29日 14:54

**复制**

- 桌面端：点击复制文本气泡中的全部内容，需要注意悬停样式，点击后图标原地变为绿色的check图标来表达复制成功，不要使用toast；复制成功3s后，操作按钮恢复到初始状态；
- 移动端：长按气泡复制，复制成功后使用toast提示“已复制”

## 智能体消息

智能体发送的消息，包含的元素会多一些，比如固定的思维链、Markdown文本、各类型的卡片、信息工具栏、推荐指令等，本章节按照自上而下顺序分别描述。

### 思维链

展示对话中思考、工具执行和过程说明。这里的目的是让用户清晰了解过程，找到问题点，便于持续优化 prompt 达到更好的应答效果，因此在做软件设计时，要**避免单纯呈现技术层面的执行节点，而忽略这部分对于用户后续优化提示词逻辑的引导**。

### Markdown

包含 Markdown 支持的全部格式的渲染（段落、标题、无序列表、有序列表、表格、代码块等）。出现 Markdown 及后面的元素时，思维链的状态一定是「已完成」。

- **出现动画**：流式输出
- **特殊需求**：

  - 【代码块】支持一键复制
  - 【链接】注意链接文字样式需要使用主题色+下划线
- **多端样式适配**：

  - **使用 shadcn 对应流式文本默认样式，只调整标准字号（--typeset-size: 16px;），这部分不需要参照 Figma 设计稿** https://ui.shadcn.com/typeset?scale=16

### 澄清卡片

用于智能体对话过程中针对需要澄清的问题，以表单形式引导用户格式化输入的卡片形式，卡片整体控件样式由平台定义，仅支持部分属性和数据的传入，来满足不同业务场景的。

> - **追问方式的选择：**参考《[智能体产品交互设计指南](https://hisense.feishu.cn/wiki/RmSbwHgfuiUyMrkNoi4cJCBsnQg#share-RwpXdyAPYoUog3xdKZecUfKNnbe)》中的描述，只在“问题较多、需枚举引导”等情况下使用澄清卡片的方式，否则推荐使用 Markdown 方式；
> - **最佳使用方式**：澄清卡片是人机交互过程中一种即时性交互行为，追问的问题理论上应该是**根据实际情况由 Agent 即时产生而非提前预置**的，因此在技术方案上，澄清卡片的表单需要是元数据驱动的方式，支持具体业务场景通过实时生成表单元数据达到“**问题随场景即时变化**”的目标；

# 四、其他交互

## 页面刷新

整体原则是“**从哪里触发，刷新后就在哪里**”，用户不管是从 index / new、chat 页面触发页面的“刷新”操作，刷新后都应该回到触发时所在的页面，并加载出最新的页面内容；

> 存在一种特殊情况，用户刚从新对话页发送指令，此时对话 id 还未生成但已经进入了 chat 页面，如果用户恰好此时触发了页面刷新，视为“**对话还未创建完成时的刷新操作**”，刷新后可到 new 页面，但应从技术实现上尽量缩短这个过程。

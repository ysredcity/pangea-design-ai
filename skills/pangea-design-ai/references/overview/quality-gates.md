# 质量门禁（Quality Gates）

> **什么时候用**：每次生成一个新场景/页面，或对已有内容做完一轮修改后，交付/预览前按 G1–G9 逐条核销，最后过一遍[反面清单](#反面清单自查)。任一门禁不过 → 先修复再交付。

## 来源与用法

G3–G8 的检查项主要来自沉浸式实测沉淀的设计评审清单与反面清单——**那是真实迭代中反复出现过的问题**，含金量高于凭推理列出的条目。规则正文在 [design.md](../design.md)，本文件只做可勾选的核销表，不重复正文。

- AI 生成后**逐条对照自检**，对不满足项直接修复。
- 能自动化的由脚手架命令覆盖：**`npm run gate`**。
- 其余靠对照检查（结构化、可复述）。

---

## G0 · 前置：需求文档已确认（生成前硬门禁）

- [ ] 需求文档已产出并**发给用户**
- [ ] 用户在**看到文档之后**给出明确肯定答复
- [ ] 需求里每项能力都判断过**能否用配置 + 场景数据覆盖**；不能覆盖的已在文档中写明要扩展什么（见 [SKILL.md](../../SKILL.md) 强制判断步骤）

任一为"否" → **停止生成**，先补需求规格化并请用户确认。

> ⛔ 禁止同一轮里既输出需求文档又生成工程代码。可跳过情形仅限：已确认文档下的增量、纯样式/文案单点微调、用户显式要求"不用出文档直接做"（从严解释）。

## G1 · 编译与类型（硬门禁）

- [ ] `npm run gate` 通过（含类型检查 + 构建 + Token 机检 + 剧本机检）
- [ ] 无新增 lint warning

**执行顺序**：先跑通类型检查再判断结果是否正常。**不能只凭"dev server 起来了、无控制台报错"就认为界面正常**——部分类型错误不会阻止 HMR 生效。

## G2 · Token 与视觉基础

- [ ] 颜色**全部走语义 Token**（`background`/`foreground`/`muted`/`accent`/`primary`/`primary-bg`/`sidebar-*`/`success`/`warning`/`info`/`destructive`），**无硬编码**、不绕过变量层
- [ ] 暗色**未单独写颜色**，由 Token 层覆盖
- [ ] 字号落在既定阶梯：正文 15px/1.6、辅助信息 14px/20px、极次要 12px
- [ ] Markdown 正文交给排版层，未在业务组件里逐元素设样式
- [ ] 已成契约的组件尺寸未被改动（动作 Badge 32px/300px、卡片 600px/12px、侧栏 240px、抽屉 320px）
- [ ] 图标全部来自单一图标库；上下文/能力图标走注册表，未在使用处就地挑
- [ ] **一组内只有一个主操作**用 `primary`；危险操作用 `destructive` 且未设为默认

机检：`npm run check:tokens`（扫描裸 `#hex` / `rgb()` / `rgba()`）。

## G3 · 结构与层级

- [ ] 界面形态选型符合[决策树](../design.md#21-界面形态选型)，未出现"为塞 AI 侧栏压缩主工作区"类反例
- [ ] **结论在过程之前可读**，已完成的过程默认收起
- [ ] 只有**正在执行中**的过程默认展开
- [ ] 层级与任务真实复杂度一致，**没有为完整性硬造的 L2**
- [ ] 有 L2 的地方都有**可查看的 L3**，且**没有 L2 套 L2**
- [ ] L2 展开后的 L3 用扁平样式，未重复 L2 的状态圆点/粗标题/竖向时间线
- [ ] 每轮智能体侧**以身份开场**（头像 + 名称）
- [ ] 深度思考**没有出现在每个执行过程里**，只用于协调型/复杂规划/自纠错三种场合
- [ ] 布局外壳未被重写（内容只在插槽内变化）

## G4 · 信息归属

- [ ] 上下文按**能否内联**正确分区：文件库/最近对话/技能 → 气泡内内联标签；本地上传 → 气泡上方附件卡片
- [ ] **专家在智能体侧**，不在用户消息里
- [ ] **连接器不进消息流**
- [ ] **同一对象在所有位置图标一致**（侧栏、输入区、菜单、已选状态、消息流）
- [ ] 对话组件优先复用现有组件，未新建平行实现

## G5 · 产物与交付

- [ ] 有产出目标的任务给出了**可点击交付物**（结论文字不算交付）
- [ ] 过程里的产物入口与最终交付**指向同一对象**
- [ ] **可点击的 Badge 背后都有真实可看内容**；内部调用类（技能/接口/脚本/状态查询/连接器）未做成可点击
- [ ] 对话流内**只有摘要**，无完整产物内容渗漏
- [ ] 容器类型选择符合[并排 / 专注判定](../design.md#353-产物容器区分并排比对与专注查看)
- [ ] **重复打开不产生重复 Tab**；容器内跳转复用当前 Tab
- [ ] 容器专属操作在各容器自己的操作栏，面板顶部只有全屏 + 关闭
- [ ] 用户附件右对齐、智能体交付物左对齐，两者共用同一套卡片与打开链路
- [ ] 面板内操作结果**同步回对话流**

## G6 · 状态语言

- [ ] 五种状态表达**唯一且未混用**（执行中 / 等待回复 / 等待批准 / 完成未读 / 已提交）
- [ ] **「需要你的回复」只在当前对话最后一轮、且用户还没回复的追问上**
- [ ] **「等待批准」用 destructive 语义**，与「等待回复」的警示语义未互借，同一轮不并存
- [ ] 运行中状态在**选中、悬停、聚焦时都可见**（悬停出更多操作时 Spinner 让位而非消失）
- [ ] **只有当前运行中的过程带动画**，历史与已完成为静态
- [ ] 状态**不只靠颜色**传达，除颜色外有图标或文字
- [ ] 模拟执行**分阶段推进**，未一次性拍出全部结果；减少动态偏好下等待压缩为立即推进

## G7 · 卡片硬约束与风险分级

- [ ] 澄清 / 确认卡片：无 Tabs/Menu 深层导航、无内部滚动、字段 **≤10**、按钮 **≤3** 且主按钮 **≤1**
- [ ] 确认卡片**不重复 AI 已用文字表达的信息**
- [ ] **高风险操作走确认卡片**而非纯自然语言确认，字段含**对象/动作/影响范围/后果/操作人**
- [ ] 确认卡出现在**即将执行的那一轮**，不挂在仅给建议或结论的回复上；卡片指明具体作用对象
- [ ] 待确认期间**输入区整体禁用**、显示等待批准提示、会话列表同步标记；批准/拒绝后均解除并回写结果
- [ ] 待确认判定来自**显式状态**，未从卡片文案、按钮名或块 ID 推断
- [ ] 写操作、高风险操作**未静默执行**
- [ ] 追问澄清：**≤2 项用自然语言，>2 项用表单卡片**；任何追问方式都可跳过
- [ ] 澄清表单：必填未齐前提交禁用；提交后字段转只读 + 显示「已提交」；未混用原生控件
- [ ] 后续引导数量 **2–4 个**，且**未出现在[禁用场景](../design.md#37-后续引导)之后**
- [ ] 权限不足、敏感信息、跨系统调用有明确提示
- [ ] 存在人工接管入口与上下文交接机制

## G8 · 响应式与动效

- [ ] **四个宽度都检查过**：桌面宽屏 → 侧栏收起 → 约 700px 窄桌面 → 659px 以下移动端
- [ ] 断点与区域宽度落在[对应形态的档位](../design.md#22-响应式与空间分配)（沉浸式 980/740/659 + 420/800/320；助手式沿用指南下限）
- [ ] 降级顺序为**先收左侧菜单栏，再降级右侧面板**
- [ ] 移动端一次只显示一个主要区域，用动态视口高度
- [ ] **没有在当前形态下无效的按钮**（窄屏强制全屏时不显示全屏切换）
- [ ] 拖拽后缩窗时动态限宽，历史宽度未挤压对话区
- [ ] 动效只解释空间关系或状态变化，**尊重减少动态偏好**
- [ ] 折叠收起态**不可交互、不可聚焦**（`aria-hidden` + `inert` + 禁用指针事件）
- [ ] 拖拽过程中无过渡动画
- [ ] **同一种效果只有一个实现**
- [ ] **切换对话时上一个对话的产物已清理**（立即，不留退出动画）
- [ ] **进入或切换对话默认定位到最新一轮**，且首次绘制前完成、无顶部到底部的跳动

## G9 · 无障碍

- [ ] 正文对比度 **≥ 4.5:1**（WCAG AA），**亮暗两套都过**
- [ ] **键盘可完成核心操作**，焦点可见
- [ ] 纯图标按钮有 **`aria-label`** 与 Tooltip
- [ ] 流式/状态区域用 **`role="log"` + `aria-live="polite"`**，未造成重复朗读或状态混乱
- [ ] 移动端触控目标 **≥ 44px**，核心操作不依赖 hover
- [ ] 图片 / 图表 / 文件结果有**文本摘要或替代说明**（图表用 `role="img"` + 说明段落）
- [ ] 文案**不责备用户**，并提供下一步帮助

> ⚠️ 沉浸式实测实现对本组的覆盖偏薄（主要落实了"不靠颜色单独传达"与"纯图标按钮有可访问名"）。其余各项在改动涉及的组件上**需要主动补齐**，不能假设已有实现都达标。

## 反面清单自查

以下每一条都是真实迭代中**出现过且会反复出现**的问题。交付前确认一条都没有：

- [ ] 没有为让结构"看起来完整"给简单任务加规划层（L2）
- [ ] 没有把内部系统调用做成可点击、点开无内容
- [ ] 没有让普通回复和某个特殊流程各自定义间距（会产生视觉漂移）
- [ ] 没有同一个对象在菜单里一个图标、在已选状态里另一个图标
- [ ] 没有用条件渲染实现悬停操作栏（会导致布局跳动），而是常驻占位 + 透明度切换
- [ ] 没有在表单里混用产品组件和浏览器原生控件
- [ ] 没有结论说"已完成报告"却没有任何可打开的产物
- [ ] 没有让历史追问持续显示"需要你的回复"
- [ ] 没有在窄屏保留没有对应形态的全屏按钮
- [ ] 没有同类动画存在两套实现（改了一处另一处不动）
- [ ] 没有把不能被配置覆盖的需求悄悄降级成"用现有配置近似一下"

## 交付前速查（一句话版）

需求文档已确认且判过配置能否覆盖（G0）· 编译过 + 先类型检查（G1）· 颜色走语义 Token + 尺寸契约未破（G2）· 结论优先 + 层级不硬造 L2 + 每轮身份开场（G3）· 上下文分区正确 + 图标一致（G4）· 交付物可点击 + 过程入口与交付同源（G5）· 五种状态不混用 + 只有运行中带动画（G6）· 卡片字段/按钮数达标 + 高风险走强确认（G7）· 四个宽度都查 + 降级先左后右（G8）· 对比度/键盘/aria-label/44px（G9）· 反面清单一条都没有。

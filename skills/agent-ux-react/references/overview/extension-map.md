# 扩展点地图

> **什么时候用**：[SKILL.md 第二道门](../../SKILL.md#-第二道门每项能力先判断能否用配置覆盖)判定某项需求"不能用配置覆盖"、并走完 [design.md 第七章六问决策流程](../design.md#七扩展新能力的决策流程)之后，来这里查具体改哪个文件。

## 为什么需要这份地图

脚手架起点是一个 3000+ 行的完整成品，你读不完。**最大的风险不是架构限制，而是定位不准**——改错地方会犯下面这些已被明令禁止的错：

- 把视图逻辑塞回页面壳层文件
- 绕过容器注册表硬写容器类型分支
- 在输入区组件的 JSX 里硬编码图标映射

好消息是**扩展点已经内建在工程里**（容器注册表、图标注册表、资源视觉映射、动作图标表），你只需要知道它们在哪。

## 查表

| 要加的东西 | 改这里 | **不要碰** |
|---|---|---|
| 新对话场景 / 改话术 / 改分支 | 剧本数据文件 | 任何视图组件 |
| 新面板内容（检索结果 / 网页 / 文件正文） | 面板数据文件 | 容器实现 |
| 新产物容器类型 | ① 扩展 `PanelView` 判别联合 ② 写容器的 Toolbar + Body 实现 ③ 在容器注册表补一条 | 面板框架壳层（它不该出现容器类型分支） |
| 新动作 Badge 类型 | ① 扩展动作数据类型的 `type` 联合 ② 在动作图标表补映射 | Badge 渲染组件本身 |
| 新上下文 / 能力图标 | 图标注册表 | 各处组件 JSX |
| 新文件类型图标 / 新专家头像 | 资源视觉映射文件 | 输入区菜单的 JSX |
| 改产品名 / 产品头像 / 侧栏菜单 / 首屏推荐 | 应用配置对象 | 组件内部 |
| 新的澄清表单字段类型 | 扩展澄清字段类型联合 + 在表单卡片补该类型的编辑态与只读态 | 其它字段类型的分支 |
| 对话流插入产品专属自定义块 | ⚠️ **当前无扩展点，见下方缺口** | — |

## 判定要点

扩展前先确认这几条，避免加完就违规：

| 要加的 | 必须先确认 | 依据 |
|---|---|---|
| 可点击的动作 Badge | **背后真有用户可查看的产物**。内部调用（技能/接口/脚本/状态查询/连接器）**不做成可点击** | [design.md 3.2.3](../design.md#323-有产物的动作才做成可点击资源) |
| 产物容器 | 用户会不会一边看它一边看对话？会 → Tab；不会 → 蒙层查看器 | [design.md 3.5.3](../design.md#353-产物容器区分并排比对与专注查看) |
| 新层级（L2） | 是否真的"先规划再分头执行"。默认答案是**不需要** | [design.md 3.2.2](../design.md#322-层级必须反映任务真实复杂度绝不为完整性硬造) |
| 新状态 | 是否属于已有四种之一。不属于 → **先补状态语言定义再做视觉** | [design.md 4.1](../design.md#41-四种状态语言) |
| 新图标 | 是否已有归属。没有 → **进注册表**，不在使用处就地挑 | [design.md 6.4](../design.md#64-图标) |
| 任何进消息流的东西 | 它是不是消息语义的一部分（决定内联 / 附件区 / 不进消息流） | [design.md 3.1.1](../design.md#311-上下文与能力按能不能内联三分) |
| 交付类任务 | **结论文字不算交付**，必须给可点击产物，且与过程里的产物入口指向同一对象 | [design.md 3.5.2](../design.md#352-交付物必须是一等公民) |

## 已知缺口：对话流缺"自定义块"扩展点

**现状**：对话流内没有"插入产品专属自定义块"的机制。组合专家身份 + 执行过程 + 正文的回复块组件是**文件内私有实现**，不对外导出，也没有插槽或注册表。

**影响**：这恰好是生成差异化产品最可能需要的扩展方式（例如要在回复里插入一个"合同风险评分卡"或"审批流程可视化"）。当前只能改对话流组件本身。

**临时做法**：改对话流组件时，在需求文档里说明"修改了壳层内部及理由"（见 [components/README.md 的公共导出 vs 内部实现](../components/README.md#公共导出-vs-内部实现)）。

**计划**：整合方案 Phase 2 补设计（插槽或注册表方案）。

## 改完之后

1. 若改了组件元数据 → 重跑 `node scripts/build-catalog.mjs`
2. 过 [质量门禁 G1–G9 + 反面清单](quality-gates.md)
3. 若新增了组件 → 在 [components/](../components/) 对应层补一份组件文档（结构见 [components/README.md](../components/README.md#每份组件文档的固定结构)）
